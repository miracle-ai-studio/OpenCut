# 历史兼容格式夹具

本目录冻结当前明确支持的历史格式，避免每次验收先用当前程序建库再降级，导致生产实现与测试一起漂移。

- `db-v1.sql` 是初始工程/修订/事务/回执/outbox 结构；依次应用 `db-v2.sql` 和 `db-v3.sql` 得到任务、进度及 Job 事件结构；新增 `db-v4.sql` 冻结独立来源记录扩展。新增 `db-v5.sql` 冻结主体、凭证摘要、项目权限与独立任务归属结构。新增 `db-v6.sql` 冻结媒体发布意图与追加事件扩展；v1–v5 SQL 夹具保持不变。
- `project.json` 记录合成历史工程、一次成功编辑、精确请求/结果，以及无版本摘要和 v2 摘要。旧 typed 序列设置请求保留 optional null；验收调用特意省略这些 null 字段。
- `results.json` 记录八类已知兼容结果，其中工程任务缺省素材锁字段、导出缺省文字布局字段，供新读取器验证兼容默认值与公开投影。

这些是从仓库保留的历史格式定义重建的夹具，**不是从已发布旧二进制采集的数据**。revision/transaction ID 与媒体路径为合成值；没有真实媒体文件的成功记录只用于验证历史读取，不能作为下载可用性证据。八类任务在不同时间引入，数据库版本 × 结果种类是兼容性组合，不是发布版本时间表。

`scripts/verify-history-compatibility.py` 独立用 Python sqlite3 构造数据库，经多个真实 CLI 进程验证并发升级、历史数据不变、旧回执重放、不同请求拒绝、升级后写入、未来结果隔离和迁移失败原子回滚。排队探测任务使用现场生成 WAV 并由真实 Worker 执行。未知/损坏/其他应用数据库必须拒绝且主文件字节不变。

修改夹具必须解释兼容承诺为何改变；不要在验收运行时从生产 Schema 或结果类型自动覆盖本目录。公开 22 工具的冻结 Schema 另见相邻 `legacy-v1-tools.json`。

`db-v7.sql` 冻结插件发布 Journal。`db-v8.sql` 冻结项目上传会话、确认块与项目素材登记表；v1–v7 夹具不变。v8 当前已验证上传基础和历史升级，项目导入公开动线尚未交付。验收脚本读取被测二进制新建空库的版本，仅用于选择矩阵终点，不从生产 DDL 生成历史夹具。打包 manifest 同样记录实际打包二进制的数据库版本。

2026-09-23 恢复验收：`db-v9.sql` 至 `db-v15.sql` 已分别冻结后续迁移增量；本目录 v1–v15 与 legacy/v2 请求摘要形成 30 格矩阵，当前源码构建的 CLI 通过 `verify-history-compatibility.py` 的 22 项检查。上述早期进度文字是当时 v8 阶段的记录，不代表当前公开导入状态。
