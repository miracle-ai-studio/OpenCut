# 音量曲线平滑与编辑体验 · 2026-10-22

用户反馈音量曲线转折尖锐、只有一个点容易操作。此轮修改 Web 控件，并通过真实 UI 将当前海南工程五条音乐的渐入/渐出改为平滑变化，原控制点 ID、时间和音量保持不变。

| Before | After | Why |
|---|---|---|
| 相邻音量点为直线，转折处斜率骤变 | 「平滑变化」复用现有缓入缓出预设，经 Rust 曲线规划一次提交全部相邻段；可切回「直线变化」 | 实际修改保存的曲线，平滑连接恒定音量段；不只给折线加圆角 |
| 42 秒挤在一张窄图里，短渐入显得接近竖线 | 属性面板默认放大开头，可切换「全段／开头／结尾」，显示所查看的秒数范围 | 单独调整 1.52 秒渐入或末尾渐出；视图切换不修改工程，时间线仍按全段定位 |
| 图高 76 px，首尾点贴边，5 px 点不好抓 | 属性图高 128 px，增加边距，22 px 透明点击区；端点圆点内缩，按 Alt 拖动为五分之一步幅 | 保留小圆点外观，扩大操作范围，提供精细调整；移动时防止原有切线越过相邻段 |
| 全长均匀取样让短曲线只有少量折点 | 在既有取样预算内，为相邻控制点之间补充时间点，曲线数值仍由 Rust 返回 | 短渐变在长片段里仍有足够的显示精度；不在客户端重写音量插值 |
| 悬浮信息含内部点 ID 和 linear | 显示秒数、百分比或 dB，控件随中英文、明暗主题更新 | 便于理解和调整，不把内部标识作为主要信息 |

## 验证

最终受影响范围为 4 个测试文件、23 项用例。第一轮 22 项通过；加入显示范围用例后，修正测试中错误的夹具时长假设及 Testing Library 的参数写法，最终曲线控件 9 项通过，其他 3 文件 14 项沿用同轮未变源的通过结果。不是额外相加的多个总数。覆盖平滑原子意图、迟到回包、Alt 细调、切线移动约束、短渐变采样、视图切换无写入及已有编辑器/预设行为。

最终 TypeScript/Vite 构建、Web 256 文件边界检查通过，保留既有大包提示。此轮只修改既有 Web 模块，不修改公共契约、Rust 或依赖，不重编 Native、重新生成契约或放宽 allowlist。Native 仍为 `069a21775bf41839ac2a2afa8172f228ff169fcd1e5254e776a6b0e193950869`，服务继续使用 59790 和原库。

在真实海南工程 `hainan-vlog-workbench-20261021` 中，逐条选择弦乐长线、钢琴主题、竖琴光点、低音根基、圆号远景并点击「平滑变化」，每条音乐一次原子提交。独立读取最终公共文档，核对所有原始点 ID、精确时间和音量不变，工程其他内容完全不变。每条音乐 25 个权威采样点，共 **125 点**，与独立的三次曲线 X 二分求解/Y 多项式期望比较，最大绝对误差 **4.44e-16**；恒定音量段不变，未超出原始音量范围。

最终浏览器只读检查覆盖中文/英文 × 深色/浅色，控件无横向溢出；实际切换全段、开头、结尾。最后恢复中文深色，并保留「开头」视图供用户预览。Alt 修饰拖动和迟到回复由组件测试验证，未声称全部物理手势和读屏验收。全站切换语言后个别既有菜单无障碍标签仍保留初始语言，本轮未改这些菜单，不将本轮结果扩为全站语言/无障碍验收。
