# CLI / MCP 接口修复与 UI 交付审查

CLI / MCP 本轮问题已修复并取得限定验证，当前本机服务已切换到最终候选。UI 独立审查的结论是**尚未达到交付标准**，详见 [UI 报告](ui-delivery-review-20261021.md)。这次没有修改 UI 产品代码。

## 已修复

| 原问题 | 当前行为 |
|---|---|
| MCP 动作清单漏项，模型无法发现已有能力 | 默认 11 个业务领域公布完整 161 个动作；22 个工作区管理操作仍属显式维护范围。领域清单来自同一份 Rust 注册表。 |
| MCP 参数只写“一个对象” | 每个动作携带对应的 Rust 请求 schema，共用定义去重；动作与参数类型一起校验，无手抄 DTO。 |
| Agent 找不到当前工程变化订阅入口 | 公开当前 main 主线摘要模板，订阅后收到变化通知。固定版本仍不变；Skill 说明重连游标、重新读取及过期提案处理。 |
| CLI 的普通工程命令无法远程连接 | 工程、编辑、任务、事件、插件和上传复用同一命令映射，经现有 SDK 连接服务；任务等待、NDJSON 续读、原始字节上传也已接线。 |
| 插件退出时带走自己的 Worker | 0.4.0 插件默认连接已启动的独立服务，会话不持有 Worker。临时 Worker 模式需显式 `--with-worker`。 |
| 连接路径或候选不匹配时容易连错 | 打开工作区前验证服务 ready、数据库路径及服务启动时记录的二进制 SHA-256；错目标、错构建或服务停止时拒绝连接。 |

默认 MCP 为 11 个领域入口，不代表只有 11 个功能；完整业务注册仍为 183 项、12 个领域。被发现的动作仍执行原权限检查，尤其 owner-local 操作不会因可发现而变成远程开放。
