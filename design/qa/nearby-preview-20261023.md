## 实现与交互

- Rust 按当前位置安排新缓存任务；SQLite 同秒任务按实际提交顺序执行，公开清单仍按时间排列。25.84 秒对应的首五项起始帧实测为 600、650、550、700、500。已入队的历史任务不自动抢占重排。
- 自动当前帧、暂停和拖动仅查询已有缓存，缺少时只渲染请求位置，不为每次选帧创建整条时间线任务。可选 `reuse_only` 由 Rust 声明生成，不另建 UI 或 CLI 业务语义。
- 优先读取当前段和附近窗口，保留同一图片 Worker 及已校验字节；释放解码器后仍可在新授权下复用字节。取消、修订、代次和资源校验保留。完整连续播放会预备前方缓存；若前方编码数据能放入 64 MiB 预算则先读取，不能放入时沿用有界窗口。冷启动完整播放仍可能等待，不能称为即时起播。
- 播放头捕获指针并立即改变位置，合并后台定位，松手提交最终位置；取消、失焦、捕获丢失和第二指针有测试。新增横向导航条；缩放及逐帧键盘操作保持工程帧率与边界。
- 播放器自动显示当前帧，移除点击播放说明；时间、逐帧、播放、缩放、快照及全屏入口整合到底栏。暂停后先显示缓存画面，再恢复原尺寸。
- 素材、音频、字体、图形、效果和转场使用卡片，预览、添加及更多操作置于卡片内。字体与图形加号直接使用原生默认计划保存并选中，普通操作不再额外审阅。字体读取实际资源与字重／样式；效果示意有明确标注，不冒充实际素材处理结果。

## 声音及起播修复

原 Chromium 路径在海南五条同步 PCM 轨道中，逐块生产速度接近或超过播放时长；后台视频生成进一步争用资源。现在已探测为不超过双声道且保持时间戳的 PCM，使用同一固定 Mediabunny 字节、同一准备器和混音器直接在 Node 执行。变调、压缩编码和离线 DSP 继续使用原 Chromium 路径。Rust 仍编译时间映射和增益事实，验证读取、授权、预算、取消与发布围栏；没有换时钟或搬移应用语义。

Node 内部投影复用原验证入口，直接传递精确 JSON 和已验证的 Uint8Array；Chromium 页面的压缩／字节传输不变。去掉进程内无意义的压缩解压、十六进制与 Base64 往返；原有位级位置／振幅共享保持。没有新增依赖。

Native 与设备各自最多 32 个 4096 帧块；48 kHz 下各约 2.73 秒、1 MiB 双声道 Float32，设备启动预备 32 块。暂停和定位立即清除旧代次的未播放块，不等待储备播完。重复调用同一 AudioWorklet 量子仅消费一次并返回相同样本；真正重叠仍拒绝，断流计数未屏蔽。

复杂段首次实播揭示起播映射通知迟到，曾跳过开头四帧。最终修复在 PCM 准备阶段向图片 Worker 传递有效的同一设备时间映射；只有实际 Worklet 消费区间才能推进画面，不创建另一时钟或虚构输出。暂停／失效后的回执不重新校准。修复后复杂段及完整播放均零跳帧。

## Host 边界说明

新增 `audio_preview/scheduling.rs` 是同一 Host 进程的本机执行协调，无新增领域模块、依赖、公共 DTO 或业务操作。后台视频逐帧开始前查询同工作区现有会话与应用的 PCM 供给额度：实际声音已经消费且数据待补时让出执行，补足后继续。冷准备、暂停、定位重置、断开、过期和完整片尾均释放等待。注册表锁不跨等待，流与状态的锁顺序保持；等待期间继续检查取消、授权、租约、总时限与无进展时限，不合成进度或延长期限。当前采用同进程嵌入式后台执行；跨进程／跨主机工作器协调不在本次通过范围。

单帧选帧和已缓存的前台绘制不经过后台等待。系统优先级实验没有解决问题，已从产品源码撤回；最终依赖实际 PCM 需求协调，而非固定休眠或操作系统优先级。
