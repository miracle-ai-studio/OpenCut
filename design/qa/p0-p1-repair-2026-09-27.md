# P0/P1 实施与核验（2026-09-27）

这是代码修复记录，不是全部 P0/P1 完成声明。当前新增宿主与端口实现、编译校核、执行收据和长素材支持；素材理解、专业剪辑算法、预览性能和完整工程复现仍有未完成部分。旧报告中的 12 条装配依赖、单文件 1 GiB 上限已由本次记录取代。

## 已落实的代码

| 项目 | 实现与边界 |
|---|---|
| D01 工具分派解耦 | `automation` 不再依赖 SQLite/native-services。公共 registry 同源生成 `ToolRequest`，应用 `ToolExecution` 端口由 host-runtime 注入；统一执行上下文、撤权检查、请求大小、domain 解析、权限检查、参数解码及拒绝审计顺序。内存后端可独立替换。宿主内部保留旧 facade 的兼容分派，未宣称全部用例已逐项拆成小服务。 |
| D02 宿主装配 | 新 `host-runtime` 集中装配数据库、媒体、CAS、预览和 Worker。CLI/HTTP/MCP 通过应用 `WorkspacePort` 和宿主的有界 I/O handle 访问；没有把具体 SQLite 类型重导出成别名。CLI 移除 5 个原生/调度依赖，数据面实际实现从入口迁出。 |
| D03 Worker 隔离 | `job-runtime` 仅保留领取、恢复、执行、重试与租约围栏发布；通过 `JobStoreFactory` / `JobStore` / `ExecutorPort` 访问实现。原生执行、监控、进度、输出准入和故障测试迁至宿主。替换执行器不能绕过最终 attempt/lease 检查。 |
| 防止依赖回流 | 22 个 crate 登记，12 条迁移例外全部删除。增加 dispatcher/scheduler 的原生传递依赖检查及 CLI 入口检查。CI 的纯行为任务加入分派/调度端口测试；远端 CI/必需检查仍属未验收边界。 |
| TS 入口与边界 | Web 控制请求共用 SDK 的 `requestEnvelope`，统一版本、request ID、错误、取消与未知提交状态校验，禁止自动重试。新增 AST 导入门禁，覆盖 75 个 runtime 文件；限制跨组件访问为 SDK 公共桥接，拒绝动态模块查找、原生依赖、别名逃逸、构建/测试入口回流。已接入 npm、Moon、CI，数据下载与 SSE 仍各自处理。 |
| source → IR 校核 | 在每次编译中核对视频/图片绑定与版本、源区间、位置/层序/变换、音频 gain/可选音流/时序、字幕文本与字体样式、关键帧区间/值/Bezier 参数；独立校核有理数时长和音频尾部。原有 V3 shape/effect/mask/transition 校核继续执行。记录禁轨、静音和仅视觉范围的排除。 |
| 执行收据 | 6 类 schema2/3 工程帧、区间、整片任务在发布前写入并同步有界 `execution-v1.json`，走 attempt 输出准入。记录准备输入、源 revision、合成图 hash、当前宿主可执行文件/FFmpeg 工具观察值、输出 hash/size；执行前后身份观察改变则失败。新增 `opencut_job_execution_receipt_v1` 查询，只读取授权的成功发布 attempt，拒绝与任务/产物绑定不符的记录。 |
| 长素材 | 公共 Rust 常量、应用上传校验、Rust/TS SDK、HTTP 入口、工程包单素材限制统一至 16 GiB，单块仍 4 MiB、最多 4096 块；项目/工作区上传预留独立限制为 32/64 GiB，工程包媒体总量仍为 64 GiB。修复 TS 旧偏移正则对 11 位字节位置的误拒绝。哈希和包复制继续流式处理。 |

Rust 嵌入 API 的原生构造入口由 `opencut_automation::Automation` 移至 `opencut_host_runtime::Automation`；这是源码迁移，公共 wire 保持兼容。使用自有后端的嵌入方实现 `ToolExecution` 并调用纯 dispatcher；见 [宿主迁移说明](../../crates/host-runtime/README.md)。

执行收据不是签名证据或独立声画 oracle，也不等于历史包原始引擎可恢复。查询验证它与受信任任务记录的绑定，不证明收据每个描述字段都能抵抗本机文件篡改。`semantic_output_verified` 明确为 false；独立像素验收另行记录。未修改旧包/旧工具 schema 来伪造兼容性。

## 验证

实际命令、计数、固定候选身份与日志摘要见 [机器证据](evidence/p0-p1-repair-2026-09-27.json)。所有媒体夹具均为本地生成，未读取或上传用户海南素材。

- 完整非 UI Rust workspace：386 项通过、0 失败；6 个 ignored 是父测试显式调用的崩溃子进程入口。Clippy `--all-targets -- -D warnings` 通过。
- 独立内存分派/Worker 注入、授权和失租不发布测试；原生 SQLite 忙锁、进度、取消、崩溃恢复、真实媒体回归。
- 编译负向检查主动删除音频/曲线、修改字幕/字体/源版本/时长/变换；用有理数比较避免不同 timebase 的相等时间误报。
- 固定 CLI → Worker → HTTP：6 个独立像素检查通过；6 个执行收据与真实产物绑定、6 次修改 attempt 的拒绝路径通过；16 GiB 上传准入和超限拒绝通过。
- 实际 PCM 独立基准：已知双声道 330/660 Hz 波形，非零源起点及时间线偏移；完整导出与区间预览都验证选中频率、0.4 × 0.5 × 0.5 = 0.1 峰值对应 RMS、片段外静音、禁用/静音轨排除及输出时长。容差仅用于本机 AAC 解码基准，不证明全部音频效果与跨后端一致。
- stdio MCP 18 组、旧工程恢复 4 组、schema5 工程恢复 16 组通过。SDK 19 项、Web 31 项测试与两者构建通过。130 个既有工具全部 schema/read_only 不变，现有 131 个工具；生成物无漂移。
- Rust 架构 22 模块、0 临时例外；14 项门禁负向测试通过。TS 门禁扫描 75 文件，包含在 SDK 测试内的 5 组边界夹具通过。远端 CI 未执行，Web 构建不等于交互验收。
- 超过 1 GiB 的本地合成 WAV：实际固定到 CAS、自包含导出、删除原文件、异工作区恢复及独立流式 SHA-256 回读；不把这一个样本当作 16 GiB 吞吐或预览 p95 验收。

验证中发现的错误已保留在初次日志中：编译校核最初错误比较相同有理时间的原始 timebase；旧大小拒绝测试仍使用 1 GiB 阈值；TS 偏移长度限制遗漏升级。修复后再验，不把初次失败计作成功。

## 尚未完成，不能关闭 P0/P1

1. **P0 严格工程复现**：原始编译器/运行器的可恢复身份入包、字体文件和版本锁、全局恢复事务未完成。新执行收据仅记录本次工程任务，不是全体分析/插件/provider 的通用执行凭据；全参数能力协商与跨后端像素/PCM oracle 不完整。
2. **P1 素材理解与选片**：人物覆盖、运动/抖动、稳定区间、重复内容的正式 provider 流程未完成，没有把本次重构当成算法实现。
3. **P1 高层联动编辑与打点**：后续增量已实现 ripple/gap/roll/slip/slide、显式选择整体移动和轨道排序，复用原子提交与撤销，声画验收见[最新台账](../architecture/headless-completion-ledger.md)。持久同步组/J-L、Marker/BeatGrid/强拍/乐句规划仍未完成；128 个底层操作的事务边界仍适用。
4. **P1 运动与遮罩**：真正稳像及裁切/残余误差报告、速度曲线/重采样、Bezier 遮罩/动画/跟踪与失败修正未完成。
5. **P1 预览与资源治理**：代理/缓存失效、冷/热 seek 指标、长素材持续播放与混合格式矩阵、全工作区写入准入仍未整体验收。执行收据新增指纹成本也需要纳入正式性能基线。
6. **P1 声画与扩展**：完整色彩管理、白平衡/曲线/LUT/scopes、音频 bus/EQ/dynamics/LUFS/TP、可移植字体，以及各类 provider 的生命周期、取消和本地处理政策传播仍未完成。

P2 的客户端产品动线、Metal 构建环境、独立云服务接入、跨平台签名发行不在本次修复结果中关闭。
