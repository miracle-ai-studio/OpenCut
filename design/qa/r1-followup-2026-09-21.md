### 2. 媒体检查／修复共享入口

新增 `opencut_media_inspect` 和 `opencut_media_repair`，CLI、MCP、HTTP 同用。输入只接受媒体内容 hash；修复必须携带读取到的 metadata_hash，内容不匹配拒绝；两个客户端同时用旧令牌修复错误元数据，仅一个成功。返回可继续操作的结构化错误详情，不静默覆写新元数据。

存储发布抽到 `asset-store::catalog`，按内容加锁、原子替换并同步；探测通过回调注入，存储不依赖 FFmpeg／网络／工程 DB。上传与修复共用 `automation::media` 的内容判型。权限和路径归属仍由工作区宿主边界约束。

真实公共动线包含：制造旧版 image/png 错误 sidecar → CLI inspect → 并发 HTTP repair → 原 URL MIME 恢复 video/mp4 → 旧令牌再次提交 409 → 改坏媒体字节后修复拒绝且元数据不变 → 工程 revision 不变。真实 stdio MCP 另验证 malformed JSON sidecar → repair 成有效音频描述 → 独立 CLI 回读一致。

完整契约与调用示例见 [媒体维护契约](../architecture/media-maintenance-contract.md)。目录修复不自动改写此前已绑定错误 Asset 的工程；应显式 plan/apply 工程修正。

### 3. 插件注册与运行约束

- manifest 拒绝重复操作名和超出包命名空间的名称。
- 尚未实现的 analysis.read 返回 CAPABILITY_UNAVAILABLE，不能作为可执行 Host 授权；既有安装在调用时也重新检查当前 ABI。
- invalid JSON 和合法 JSON 中的无效 Operation，均由真实 WASM 组件返回并验证为 INVALID_PLUGIN；工程不改变，之后正常插件计划仍可执行。这确认了原有错误归因路径，不冒称本轮才首次实现 INVALID_PLUGIN。
- 重验发现 macOS `/var` 与 `/private/var` 路径规范化差异影响新增运行时校验，已修复，未放宽包根路径约束。

`verify-plugin.py` 11 项公共检查通过；插件实际执行、授权、fuel、并发安装等 9 项 Host 回归通过。新校验会拒绝旧 Host 曾错误接受的权限／名称，属于显式纠错，不伪装为仍受支持。

### 4. 共用错误映射

CLI exit code 和 HTTP status 改由 `automation::error_policy` 一个映射来源控制。元数据版本冲突为 409／5，缺能力为 422／6，完整性和存储损坏保留服务端错误；不依据未知错误自动重试写入。

`JOB_WAIT_TIMEOUT` 从旧实现的 CLI 7 修正为设计 §15.2 要求的 124；取消保持 7、已排队任务不因等待超时被取消。相关旧断言已按设计修正，实际 CLI 动线通过。此次没有修改 error envelope 的 JSON 形状。
