## 新发现并修复的音频问题

公开任务的脉冲验收先失败：正常速度源第 9600 个采样，导出解码后出现在 8576。隔离同构链路确认 `atempo=1` 会对这个稀疏脉冲产生 WSOLA 窗口位移；不是仅凭 AAC 延迟推测。

修复使用整数交叉乘法判定源时长与序列时长完全相等，此时绕过 atempo。最终两条公共 render.project 的脉冲在 9600／9616，既证明绝对位置，也证明 1/3000 秒的采样偏移。失败证据保留在本轮较早的 journey 目录，不放宽门槛掩盖失败。

## 兼容边界

- v2 摘要不约分 params／metadata／参数 value 等不透明数据，不改变操作顺序。旧事务仅在其记录可重新生成原 legacy digest 时允许语义恢复；带预处理资产的记录不能被当成原请求猜测。
- 当前数据库 schema 仍为 3；旧二进制不理解新 v2 摘要，因此不能宣称降级后新请求仍可幂等重试。完整升级／降级矩阵需在 R2 固化。
- 已存在的错误媒体 sidecar 不静默覆盖；初始验收时修复入口未完成，随后已在 [R1 后续验收](r1-followup-2026-09-21.md) 增加 compare-and-repair，并在本轮用当前 debug 二进制重验，见下方媒体维护收据。
- Blob 获取每次核验并使用磁盘副本保证校验和下载一致；大文件性能及临时文件平台支持未完整验收。

## 2026-09-25 QA-07 后续复核

新增 [独立音频同步验收](evidence/r1-audio-sample-sync-2026-09-25.json)：公开 HTTP 上传 44.1 kHz PCM 脉冲，写入固定修订，提交 `render.project` Job，下载并核对产物 SHA，再独立解码 AAC。1/7 秒序列起点映射为第 6857 个 48 kHz 样本；常速、4/5 变速以及变速后在精确中点拆分，三个版本的脉冲均与映射后的样本位置完全一致。

复核首次发现两个变速风险：WSOLA `atempo` 会移动短瞬态；滤镜时钟经过 `adelay` 后未重新规范化会裁掉头部延迟。修复使用精确整数时间比选择最近 48 kHz 的变调采样率，变速后回到 48 kHz，再按采样数延迟并重置滤镜 sample clock。Classic 源码也确认 `maintainPitch` 默认关闭，且 schema v1 不表达保音高；所以当前与其默认播放速率模式一致。若整数采样率逼近使整段端点偏差超过一个输出样本，`/v1/render/preflight` 会返回 `CAPABILITY_UNAVAILABLE`，不排队执行。保音高仍是未表达能力，不以此收据宣称支持。

本轮音频同步 binary SHA-256 为 `32c56d1bbe9ab26da8407563aeb8160ffda00dfad2ec3a59c8f0653e0656e0d6`。`cargo test -p opencut-media -p opencut-project-render --offline` 通过（media 24、media integration 21、project-render 24 和文档测试）；HTTP 动线覆盖 3 个真实导出和 1 个 preflight 拒绝样本。QA-07 的代表性常速、变速、拆分与 preflight 窗口现已通过；R1 仍不整体放行，页面 QA-01–03 按用户要求暂缓，QA-05 跨 FFmpeg／平台矩阵、QA-06 大文件／临时文件矩阵继续按台账列为剩余项。

## 2026-09-25 QA-05 容器品牌与白名单格式矩阵

MP4 与 QuickTime MOV 在 FFprobe 的 `format_name` 都是 `mov,mp4,m4a,3gp,3g2,mj2`；仅靠该字段会把 MOV 错标成 `video/mp4`。`ffprobe` 的 `format.tags.major_brand` 分别为 `isom` 和 `qt`。新增可选 `format_brand` 到 Rust 媒体探测结果、公共 Job 视图和生成的 TS/OpenAPI 契约；上传和 `media.probe` 都读出它，MIME 判型不参考文件名。相同别名下，3GP／3G2 也以 brand 区分为 `video/3gpp`／`video/3gpp2`。

以当前 debug CLI 通过 [24 项公共格式矩阵](evidence/r1-media-format-matrix-2026-09-25.json)：上传探测白名单中每个 demuxer 家族均以误导扩展名上传，并核对资产 kind、MIME、授权原始媒体回读字节及 SHA；当前 FFmpeg 8.1.2 实测包括 MP4/MOV/3GP/3G2 音视频、Matroska/WebM、AVI、MPEG-TS/PS、WAV/MP3/FLAC/OGG/ADTS AAC/M4A、PNG/JPEG/WebP/BMP/TIFF/动画 GIF。MP4 与 MOV 的 brand 还通过公开 `media.probe` Job 验证。

契约校验保持旧 22 个 leaf tool 不变，127 个当前工具契约与 TS SDK 构建通过；历史 Job result 缺少 `format_brand` 时仍可读取。Matroska/WebM 因 FFprobe 共用且无法判定具体品牌，保守返回 `application/octet-stream`。R1 其他 FFmpeg／平台和更广编码组合仍未验。

## 2026-09-25 release 候选媒体复验

独立 review 发现 FFprobe 的 `mov,mp4,m4a,3gp,3g2,mj2` 共享别名在 major brand 缺失或未知时不能安全映射到 `video/mp4`。判型已收紧为只认明确 MP4 brand；不明确时返回 `application/octet-stream`。用 release CLI 通过 [25 项真实 HTTP 格式矩阵](evidence/r1-media-format-matrix-2026-09-25.json)，包含 MP4、未知 brand、QuickTime MOV、3GP/3G2 音视频、Matroska/WebM、其他音视频与图像；每项核对错误扩展名上传后的 kind/MIME 和原字节 SHA 回读。
