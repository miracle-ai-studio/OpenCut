# 统一任务契约

当前任务和渲染主入口已静态接线，派生 SDK/OpenAPI 尚未统一生成，源码未构建或验收。

`opencut_job_submit` 接受渲染、固定素材分析、场景转写及 owner 本机源任务；渲染专用入口 `opencut_render_submit` 使用同一个 Application 用例与原任务队列。工程请求绑定固定修订；本机源访问在打开路径前核对 owner 权限。没有原始任务写入或查询 API，也没有客户端协议选择。

读取、分页、变化、取消分别使用 `opencut_job_view`、`opencut_job_query`、`opencut_job_changes`、`opencut_job_request_cancel`。CLI 等待和 Rust/TS SDK 都返回同一 JobView。执行输入、路径、租约、attempt 和原始诊断留在 Application 内部执行记录中。失败与不可用结果分别明确报告，不伪造空成功结果。

成功结果只有 `result:{kind,data}`。Rust 的 `job_results` 声明产生封闭联合类型、发现 schema 和客户端类型；SDK 检查成功状态、结果可用性及具体 kind。不存在扩展结果槽、开发计数器、手写结果白名单或解码失败后改用另一协议。历史任务仍由原存储 kind、输入/结果校验器和产物围栏验证，验证后按明确映射投影到当前结果，不改写任务行或证明。旧场景转写没有 Classic PCM 证明时 `audio` 为空；它不能冒充具备该证明的字幕写入来源。

完整帧、音频、视频分别使用渲染请求的 frame/audio/video 选择。音频和视频的可选 range 表达整段或区间输出，范围保留原场景时钟和母带后裁切规则；视频保留格式、质量和音轨开关。旧子集帧/视频生产入口和能力探测链不再注册。`opencut_render_capability` 一次返回各输出可用性及真实选择。视频预检使用相同格式/音轨/范围准入、资源校验及运行时/编码器检查，不创建任务。历史只读工程须显式转换后提交新输出；已经接受的历史任务仍由原执行器完成。

工程/任务事件使用同一不透明游标、筛选绑定和类型化记录，CLI NDJSON 与 HTTP changes stream 共用。断线后从最后完整消费的游标继续；等待、断线和超时不取消持久任务，取消必须显式请求。旧数字序号 SSE 和原始事件 API 已退出注册。

产物引用绑定 job_id、哈希、大小和 MIME；生成引用不代替下载时的当前权限和真实内容校验。原幂等请求、固定修订、授权/策略、取消、租约和原子发布语义保留。历史产物和候选证据保持原身份，不能因接口收敛而标为当前源码通过。

现有契约及行为检查会在所有静态接线完成后，使用同一显式集成二进制生成并按影响范围集中验证。旧消费者夹具、部分验收脚本和剩余语义命名仍在收尾；不得将语法或注册扫描称为构建或运行验收。
