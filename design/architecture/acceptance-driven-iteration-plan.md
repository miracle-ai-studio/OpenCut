## 1. 交付原则与依赖

先保护用户工程和请求目标，再稳定跨入口契约，随后逐步完成协作、观看、理解、完整编辑和交付。每轮以一个可使用的产品动线交付，代码实现、公共入口验证、真实 UI 验证分别记录。

主依赖：R0 → R1 → R2；R2 后 R3、R4、R5 可按接口依赖并行；R6 分批接入这些能力；R7 完成各宿主与整体验收。R5 的分析产物模型不依赖连续播放，R6 的工程包也不必等待全部效果完成。

保留 Rust 领域／应用层、TypeScript React、GPUI、SQLite/CAS 和隔离媒体 Worker。模型服务可使用 Python 或远程 Provider，但不直接修改工程。不引入微服务拆分，不整仓重写，也不按 crate 数量衡量分层质量。

## 3. R1：修复数据正确性与交互状态

交付：连接、编辑、重试、恢复、上传和下载行为可信。

| 工作项 | 实施契约 | 必须走通的验收动线 |
|---|---|---|
| QA-01 连接目标 | 分离表单地址、待连接目标、已激活会话；切换时禁用写入，新连接成功才原子替换上下文；失败进入明确未连接状态，旧工程可只读展示 | A → 不可达 B → 点击编辑，A/B 均无写入；A → 空 B，不携带 A 的项目上下文 |
| QA-02 异步回包 | 所有读取／创建／历史响应绑定 connection epoch、project ID、request generation；提交前校验当前上下文 | 延迟 A 历史回包后切 B，B 不被覆盖；新建与选择交错也不串项目 |
| QA-03 撤销状态 | `act` 返回显式成功／失败；只有成功恢复才改历史／redo；新编辑和外部提交使不再适用的 redo 失效 | undo → 新编辑 → redo 不可用；恢复冲突保留真实状态；切项目后无遗留 redo |
| QA-04 幂等 | 版本化语义摘要，精确约分时间；不改变有语义的操作顺序；摘要算法升级兼容既有成功记录 | 1/2 与 2/4 同键得到原结果；改真实参数拒绝；升级前成功请求在升级后仍返回原结果 |
| QA-05 媒体识别 | 通过内容探测确定类型；扩展名只是提示；内容级元数据不可被重复上传覆盖，原文件名属于导入记录 | MP4 改名 png 后拒绝或仍识别 video；原 URL MIME 不变；截断文件明确失败 |
| QA-06 产物完整性 | 下载前检查已发布产物的 size/hash，损坏返回结构化错误；历史执行成功与当前产物可用性分别表达 | 文件截断／同大小改写均不能返回可用成功产物；完整文件可下载且 hash 匹配 |
| QA-07 音频时间 | 将精确序列时间映射为目标采样格点，明确舍入规则，内部避免整数毫秒量化 | 公共渲染任务的已知脉冲在解码后对齐预期采样点；显式处理编码器 delay/padding，覆盖 split／retime |
| QA-08 attempt 清理 | 依据任务、attempt、lease 和发布引用统一清理；禁止按任务类型零散特判 | 真实进程在输出 rename 后、发布前被终止；恢复后仅有效产物保留，旧输出回收，当前 attempt 不受影响 |

实现补充：旧幂等记录必须先核实是否保存了足以还原语义的原请求。可还原则迁移／双摘要比较；不可还原则保留 legacy 匹配规则并显式版本化，禁止用结果猜测请求等价。该限制应在兼容说明中公开，不能伪称所有历史请求均可规范化。

同步修复：统一错误分类及 CLI/HTTP 映射、插件重复贡献名校验、插件无效输出归因；未实现的插件 Host 权限不作为可用能力发布。

放行：八项问题有对应证据；源码风险完成可控竞态复现后修复；真实 UI、CLI、HTTP 回读结果一致；原固定修订／取消／恢复动线无回归。若存在遗留项，R1 只能标记部分完成。

| 媒体求值 | 从现有 full/direct/range helper 抽出后端无关合成描述 | FFmpeg 和后续 GPU／Web 后端使用同一时间、图层、字幕和音频语义 |

契约必须明确：Time 的规范形、稳定对象 ID、schema/API/plugin 版本分别治理、expected_revision、幂等作用域与摘要版本、actor 来源、结构化错误与可重试性、Job 接受和完成区别、事件游标与断线恢复。具体新增 DTO 先冻结示例和兼容规则，再改生产实现。

API/MCP/CLI：建立同源的 operation/query/job 能力注册；生成 JSON Schema、OpenAPI、TS 类型与薄 SDK；Rust client 与 TS client 共用一致性 fixture。MCP 工具／资源／提示使用相同查询和操作规则。CLI JSON/NDJSON、退出码、取消等待与取消任务保持独立，禁止 SDK 自动刷新 revision 后重发写请求。

放行：旧数据库／旧请求／旧成功结果的版本矩阵通过；跨 HTTP、MCP、CLI 产生相同语义工程；SDK 从独立消费项目运行；CI 检查契约生成漂移和禁止依赖。按边界逐项迁移，不要求一次拆成大量 crate。

## 5. R3：完成人机协作与可撤销编辑

交付动线：Agent 编辑，用户即时看到变化；用户补字幕后，Agent 撤销自己的操作而保留字幕。

- 工程事务事件随提交写入 outbox；UI 按游标订阅、去重、断线续接，过期游标触发快照重建。
- 每次事务保存来源、受影响对象／属性、可显示 diff，以及足够生成逆操作的信息。
- 选择性撤销生成新事务，以当前 head 为前置条件；互不依赖的后续编辑保留。涉及删除对象或后续依赖时返回具体冲突，不自动恢复整工程。
- 重做具有分支／因果前提，不是任意历史 snapshot restore。完整恢复继续作为独立动作呈现。
- 提供明确人工接管状态；客户端撤销待提交意图，不把关闭 UI 当作取消已接受任务。
- 增加显式分支创建／比较／合并计划；首轮合并支持范围外的冲突明确拒绝，不承诺任意 CRDT 合并。

放行：真实浏览器与外部 CLI/MCP 同时编辑；覆盖断网重连、重复／乱序事件、双标签页、旧计划冲突、选择性撤销和依赖冲突。人工字幕在 Agent 撤销后仍可编辑。

## 6. R4：连续预览与媒体质量

交付动线：用户真实播放工程、暂停、seek、继续；Agent 获取同一修订的可核对观看状态。

- 先完成共享合成求值描述，再按 continuous-preview-plan 实现 Session；交互 Session 与持久化 Job 分离。
- 实现单 owner lease、generation、TTL、有界缓冲、统一资源清理与合法性检查。非法 seek 不破坏正在播放的流。
- 首个后端使用持续编码流；Web 使用真实媒体时钟。producer progress 与客户端 presentation observation 分开，不把已编码位置写成已观看位置。
- 后续以实测瓶颈决定持久 decoder、缓存、GPU/WebCodecs 路径；encoded stream 通过不等于低延迟能力通过。
- 独立检查 preview／export 的图层、字幕、色彩、变速、音量包络、VFR、NTSC 与混合采样率语义。

放行：真实浏览器播放和出声、快速连续 seek、后台切换、断流、慢消费、owner 交接、长播放均通过；旧 generation 不污染新画面，无遗留子进程或持续内存增长。Agent 在 telemetry 过期时明确报告未知／陈旧状态。

性能门槛在 R0 的指定硬件／素材上冻结：记录首帧和 seek 的冷／热 p50、p95、掉帧、A/V 偏差、CPU/GPU、内存峰值。阈值要在优化前记录，不根据本轮结果反向放宽；未冻结前不能宣布低延迟达标。

## 7. R5：素材理解与 Agent 编辑闭环

交付动线：真实中文访谈 → 找出三个有来源的重点 → 一分钟竖屏剪辑计划 → 字幕和配乐 → 预览修正。

- 素材元数据、缩略图、波形、静音、镜头、转写、词级时间和说话人以持久化 Job 生成，支持取消、重试与恢复。
- AnalysisArtifact 绑定素材版本 hash、分析器／模型版本、参数摘要、源时间坐标、语言、置信度或未知标记、可追溯来源；模型更新不覆盖既有分析结果。
- 提供分页、区间、字段选择和预算受控的查询；搜索返回源片段、文本／帧证据与来源，不只返回自然语言结论。
- 先交付真实可用分析 Provider 适配，不强制从零训练模型；Provider 细节不得泄露进编辑内核，凭证和授权由宿主管理。
- Agent 编排作为客户端完成“读取 → 计划 → 校验 → 提交 → 检查 → 修正”，不建立第二套可写工程状态。
- 字幕既能从词级分析生成，也能人工编辑；纠错保留来源，剪切／变速后的字幕时间映射由共享规则决定。

放行：使用未预填剪辑点和转写结果的真实素材，完成上述端到端动线；人工评审重点是否有来源、语义是否被剪坏、字幕错漏与时间偏差；复核取消、Provider 超时和源素材替换。受控结果可测编排，不能代替真实分析质量验收。

## 8. R6：完整编辑能力、插件与工程交付

拆成三个独立验收批次，不能用“高级能力”一个大任务掩盖缺口。

### R6-A 编辑能力与 Classic 迁移

按完整设计逐项补多轨操作、复制／布局、文字／图形、字幕导入导出、关键帧曲线、完整变速映射、效果、转场、遮罩、音频混合及对应 UI。每个参数必须经过 schema、领域校验、计划、求值、预览、导出、保存重开全部环节；未渲染参数不能展示为已支持。

Classic 优先复用纯算法和 fixture：placement、animation/retime、字幕解析、参数描述；评估 effects/gpu/masks/compositor 的独立编译及固定场景；UI 面板只迁移交互，转换为新操作。Classic storage/commands/playback 不作为第二套工程、撤销或时间权威。

提供 Classic 工程导入：识别格式版本，映射、校验并输出不支持／损失清单，保留原文件；不能静默丢弃效果后声称完整导入。对每个迁移条目记录来源、复用边界、语义差异和验收样例。

### R6-B 插件能力

按依赖顺序交付声明式模板／样式、分析器、Provider、效果／转场、导入导出和受限 UI；完善现有 planner 的 analysis Host ABI。每类包含 manifest/schema、版本、权限、资源预算、取消、错误归因和可运行示例，不以空注册项计数。

WASM 计算、外部 Provider、GPU 工作分别实施资源边界；无默认宿主文件／网络权限。Provider 的外部任务 ID、幂等与对账需持久化，进程恢复不能重复产生外部副作用。

放行：真实插件安装、调用、死循环、超额内存、无效输出、超时、取消、升级和卸载动线通过；缺效果插件时保留工程原始节点，正式导出明确失败；独立插件作者可按文档完成接入。

### R6-C 可携带工程与恢复

实现 linked／self-contained 工程包、素材／字体／插件／工具版本锁、来源与缺失依赖报告、导入校验、迁移和可恢复 GC。GC 引用根包含工程历史、活动任务、Session 与保留包，不能仅按当前 head 删除素材。

放行：在干净工作区／第二台机器导入包，断开原素材目录后仍能继续编辑和导出；缺失或不可分发依赖明确列出。验证解包路径逃逸、截断、配额不足、发布前崩溃、旧工程升级、GC 中断恢复。导出检查报告与工程版本及 artifact hash 关联。

## 9. R7：宿主接入、发布与整体验收

- GPUI 接入共享应用服务，完成实际时间线、属性、预览、任务和协作动线，移除能力占位。
- 浏览器独立运行接入 WASM 领域桥接、IndexedDB/OPFS、支持范围内的媒体后端；验证配额、断电式关闭、权限丢失、多标签写入所有权。
- 脚本面板使用独立 SDK，具备计划预览、日志、取消和错误定位；不能访问 UI store 绕过应用层。
- 移动端先落实宿主／FFI／文件／编解码与生命周期，再验证前后台、保存、任务中断与恢复；独立 daemon 不是前置条件。
- 每个平台发布具体能力矩阵；未实现的平台或能力保持未完成，不能用 capability=false 抵扣完整目标。
- 完成安装、升级、数据库／工程迁移、依赖诊断、故障日志和可执行恢复说明；升级失败不丢工作区。

最终放行：原设计 §22.2 十二项全通过；真实访谈从导入、理解、编辑、人工修正、导出到打包重开全部通过；支持平台性能门槛通过；没有未关闭的 P0/P1，P2 有明确处理决定和剩余影响。表述为“指定版本、平台与场景通过”，不使用“保证没有 bug”。

## 10. 执行组织和每轮交付物

责任按工作流分为应用／协作、领域／媒体、协议／SDK／插件、产品 QA／集成。实际人员或 Agent 分配可调整；本方案不自动启动开发。共享 DTO、根配置、数据库迁移由集成负责人协调；并行修改前固定接口、文件边界和兼容 fixture。

每个任务至少包含：需求 ID、前置条件、输入输出、失败／取消语义、兼容方案、文件范围、产品验收动线和证据路径。开发自验后，由另一执行者通过公共入口独立复验。不能只审核同一实现者写的断言。

每轮固定交付：

1. 可运行版本与变更范围；适用时附数据库／契约迁移说明。
2. 真实动线请求／响应、UI 记录、工程差异及媒体产物证据。
3. 受影响回归结果、缺陷状态及未验证环境。
4. 更新需求／Classic 迁移台账和 implementation-status；功能实际通过后才提高 capability。

不以提交数量、测试数量或 Agent 数量承诺完成日期。R0/R1 得到实际耗时和浏览器基线后，再按关键路径估算后续轮次；环境依赖、Provider 质量、编解码兼容和平台接入单独列出。

## 11. 首轮可执行范围

立即进入 R0 + R1：先固化现有复现，再按 QA-01/02/03 → QA-04 → QA-05/06 → QA-07/08 关闭问题；独立模块可并行，但每次对外协议变更先做兼容设计。工程同步和选择性撤销属于 R3，不混入首轮 bug 修复扩大范围。

首轮完成后得到的是“已验基础链路的可靠版本”，不是完整产品。随后按 R2 收拢契约，以 R3、R4、R5 三条产品动线推进，最后完成 R6/R7 的范围和平台验收。
