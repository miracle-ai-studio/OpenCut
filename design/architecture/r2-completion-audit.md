## 权威分层

| 层 | 责任与边界 |
|---|---|
| Core 与纯契约 | 时间、工程操作、媒体与 Job DTO；不依赖 SQLite、FFmpeg、HTTP 或文件系统。 |
| Application | 工程、任务、权限、预算算式和审计用例；通过端口提交原子业务状态，公共结果不暴露 Worker 输入和原生路径。 |
| 原生适配器 | `sqlite-store` 是业务事务权威；`asset-store`、`job-runtime`、`plugin-host`、`storage-budget` 分别管理固定内容、执行、WASM 和原生写入预留。文件发布与 SQLite 提交通过显式 journal／恢复结果表达，不假装跨存储原子。 |
| 宿主与客户端 | `automation` 装配用例；CLI、HTTP 和 MCP 做传输／身份适配。TS/Rust SDK 消费生成契约，不持有另一套业务规则。 |

## 已验证的 R2 能力

- 工程创建、计划、原子编辑、幂等重放和固定修订读取；历史 v1–v16 × 两摘要的 32 格兼容矩阵。
- 项目上传原始字节、封存导入、项目资源查询、显式暂存释放；TS 和 Rust SDK 可在同一会话按确认偏移接续上传。公共 Job 视图、真实 Worker、产物下载和 SSE 由独立消费者验证。
- 工程范围身份和权限、受限预检、拒绝审计、发布维护日志；CLI、HTTP、两种 MCP 的授权与撤权由真实进程验收。
- CAS 固定、审阅式孤儿清理、真实 FFmpeg 输出与字幕的内核上限和 attempt 生存期；插件 planner 的真实 WASM 执行、安装／发布恢复和项目授权。
- 原生预算账本覆盖 12 类受控 payload 写入，保留锁跨进程和子进程生存；实际盘满、WAL 检查点、Worker 强杀、下载背压和目录别名拒绝均有独立动线。完整定义见[写入准入契约](storage-admission-contract.md)。

## 不满足 R2 完成条件的边界

1. `enforces_all_workspace_writes=false` 必须保持：管理型 SQLite 的主库、WAL、主 journal、SHM 和匿名磁盘临时文件已通过工作区绑定 VFS 做写前控制预留，本机 owner 也可绕开不可达数据库恢复预算策略。SQLite 打开的匿名临时文件会立即 unlink，目录扫描无法观察活动字节，因此按文件句柄保持预留，关闭后释放；具名或 SQLite 后续新增的未识别文件类型仍拒绝打开。8 MiB 实际分配的 repair 预留已在真实 64 MiB 盘满卷上支持排队 Job 取消、终态上传释放和补足；停机／强杀后运行态 Job 的孤儿写者围栏与终态取消也已按[本轮验收](../qa/r2-running-worker-repair-2026-09-24.md)核对。但预算／业务控制元数据的严格物理保证、外部直接写入、活跃连接下的无停机 repair 切换及完整并发故障矩阵仍不在放行边界。不能仅改能力位。
2. 成功 Job 产物已有显式 release、默认保留状态、持久引用观察和可审阅计划；原生路径及 `file://` URI 别名已按文件身份识别。历史素材、插件版本及未来连续预览会话尚未形成可执行的统一保留图。删除前仍需引用发布门闩内的活跃重检、持续预览租约、删除回执、失败恢复和跨机器工程包语义。
3. 当前包是本机 debug 包。release 构建、其他平台、升级／安装、真实旧用户数据库和长视频／VFR／中文访谈性能尚未形成完整证据；Web 与桌面还缺真实产品操作验收。

下一执行顺序是：深化控制元数据的物理准入与故障恢复、运行中任务与并发故障的 repair 恢复及预留容量定标，随后产物引用和保留，再做 release／跨平台及多宿主验收。R3–R7 的选择性协作、连续预览、素材理解、完整编辑和宿主交付按[总审计](../qa/r0-r7-current-audit-2026-09-23.md)另行推进。
