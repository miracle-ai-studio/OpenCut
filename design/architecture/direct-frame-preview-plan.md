# 直接合成工程帧：下一阶段实施边界

状态：直接 PNG 接口和执行路径已落盘，首批真实公共链路、执行中取消和崩溃恢复验收已通过；完整边界矩阵及低延迟优化继续推进。它推进完整架构中的低延迟预览，不替代连续播放、区间预览和最终性能验收。

## 当前依据

`job-runtime` 的 `preview.project_frame` 先执行整个序列的 H.264/MP4 渲染，再抽取 PNG。`media::render_timeline` 创建全时长底图，通过绝对序列时间处理 overlay、字幕和动画；源视频在 filter 中 trim、retime、fps，音频另行混合。该模式的质量标签是 `encoded_project_frame`，已有公共像素、时间、分割和取消验收。

## 必须保留的契约

- 现有任务种类及其默认行为保持；不能把直接合成 PNG 静默标成 `encoded_project_frame`。新的执行方式需要显式能力和请求入口，以及不同质量标签。
- 输入继续固定 revision、sequence、素材版本；时间使用有理数和同一帧对齐函数，范围维持半开区间。
- 直接帧不承诺与有损 H.264 导出逐像素相同。旧编码帧测试保持原门槛；新路径分别验证几何／颜色预期，并在固定样例中评估与编码帧的差异，不能凭空保证通用 RGB 差不超过 2。
- 不需要音频解码的单帧请求，应显式定义视觉依赖集合。序列结束时间仍需考虑完整工程时间结构；只有音频的有效区间可产生黑场，不能因没有视觉片段而改写时间语义。
- 已解析类型必须固定请求用途与依赖范围，不能把“仅解析视觉素材”的对象传给完整音视频导出。新增帧用途后应扩充此类型边界，而非复用不完整的全序列声明。

## 实施路线

1. 提取并复用合成图语义，新增直接输出 PNG 的媒体执行路径。图层顺序、contain、透明边缘、字幕布局和绝对序列动画时钟保持一致。单帧路径不构建音频 graph，不产生完整 MP4 中间产物。
2. 初期可从较早位置解码至目标帧；必须实测成本并明确该限制。它是准确单帧任务，不因此宣称实时拖动或连续播放完成。
3. 验证正确性后，再引入活跃图层筛选、关键帧 preroll 和输入 seek。VFR／变速不允许用 nominal fps 推算代替真实 PTS；源 seek 后仍须准确裁决。
4. 窗口化引入显式序列 origin：图层与字幕区间减去 origin，动画仍先对齐绝对序列格点，再减 clip 起点。不能先独立舍入 clip-local 时间。
5. Worker 延续 attempt 私有输出、取消清理、锁定媒体和成功后发布。首轮不需要缓存；后续缓存键必须包含内容依赖、精确时间、画布／fps、后端与字体依赖，失败和取消结果不缓存。

## 验收证据

- 原编码帧接口的公共验收不退化。
- 直接帧产生 PNG，实际执行过程中不存在完整 MP4 编码／音频处理；不能仅凭返回字段声称优化完成。
- 真实 VFR、非零源 PTS、B 帧、NTSC、分数终点、非格点 clip 起点、0.5／2 倍速及最后有效帧。
- 真实分割事务前后同一全局时刻的画面连续；Hold／Linear 的位置、旋转、缩放、透明度独立像素与边界验证。
- 多轨透明合成、图片、黑场、中英与 RTL 字幕、字体回退和字幕起止半开区间。
- 缺失未使用音频不阻塞视觉帧；缺失必需视觉内容仍明确失败。
- 真实执行中取消及 Worker 恢复，不残留私有输入／帧，不发布部分产物。
- 时域效果未来必须声明历史帧需求；无法保证正确窗口化时显式拒绝，不能静默改变效果。

接口已冻结为 `preview.composited_frame`、`CompositedProjectFrameJobResult`、`composited_project_frame` 质量标记；契约由同一任务注册表生成，旧编码帧接口保持。实际已通过的场景和剩余范围以 `headless-completion-ledger.md` 为准。
