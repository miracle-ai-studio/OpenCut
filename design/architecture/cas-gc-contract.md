# 显式 CAS 回收契约

数据库 schema 12。新增纯 DTO、Application 原子端口、SQLite 计划/步骤记录与原生目录锁；CLI、REST tools、stdio MCP、Streamable HTTP 与 TS/Rust SDK 使用同一注册定义。CAS 增量提供四个工具；完整工具数量以宿主注册表为准。

## 范围与所有权

仅 LocalOwner 可以发现、计划、检查或执行回收。目标仅包含 `asset-store/<前两位>/<64 位 SHA>` 的规范内容对象，以及 `.capture-<标准 UUID>` 捕获临时文件。不会删除上传分块、媒体目录、插件包、已发布任务产物、工程历史或外部来源文件；这些类别需要独立保留/释放契约。目录本身不会删除。未知名字不会作为可删除候选。

CAS 是工作区的私有内容目录。回收要求工作区目录中只有一个非别名 SQLite 主库，拒绝同目录其他 SQLite 文件、主库硬链接和工作区顶层符号链接；目录检查在 CAS 排他锁内完成。检查文件头只用于识别可能的其他 SQLite 主库，不返回原始名字或内容。手工跨工作区共享/别名 CAS 不是受支持布局；独立工作区应通过公开导入复制内容，不能把另一工作区的内部 CAS 路径当作永久资源 API。

Unix 原生实现以 CAS 根目录 inode 的共享/排他 OS 锁协调。迁移/首次启用前必须停止旧服务、Worker 与其他旧版写入者；旧进程不参与此协议。新版本素材捕获从临时写入开始持共享锁，工程绑定一直持有到 SQLite 引用提交；任务捕获也一直持有到任务接受。只读 CAS 解析持共享锁且不创建锁文件。Collector 使用非阻塞排他锁，忙返回 `STORAGE_BUSY`（HTTP 429，CLI 7）。进程被终止后 OS 释放锁，没有持久“忙”标记需要清除。

项目导入 Worker 发布的内容哈希在接受的 `media.import` 输入中已经固定；完成时结果必须匹配该输入。因此从 CAS 发布到 project_media/成功结果提交的窗口始终有持久 Job 引用保护。后续新增 CAS 生产者必须遵守“发布至引用提交持锁”或“发布前已有固定内容引用”不变量。

## 工具与动线

1. `opencut_cas_gc_plan`：输入稳定 `idempotency_key`、`limit`（默认/最大 100）和可选 `after`。检查引用并持久化计划，不删除文件，所以标记为写操作。相同键与规范化参数返回同一计划的当前状态；改变参数返回 IDEMPOTENCY_KEY_REUSED。计划哈希绑定计划 ID 和私有对象身份；公共输出只包含对象哈希/捕获 ID、逻辑大小、保护计数、来源和状态。
2. `opencut_cas_gc_query`：默认发现未完成计划。`limit` 1–100（默认 50）限制检查的计划行数；过滤后可能空页仍有 next_cursor，客户端必须继续翻页。游标绑定过滤条件和本工作区中实际存在的计划；换过滤条件或工作区须从空游标重新发现。各页是一致读视图，跨页状态随执行变化。开启 include_complete 可查看历史；查询不触发回收。
3. `opencut_cas_gc_inspect`：按 plan_id 读取完整计划与逐项结果。请求超时、失去响应或进程崩溃后先检查，不能把通信失败当成未执行。
4. `opencut_cas_gc_execute`：明确提供 plan_id 和 expected_plan_hash。在排他锁内重新读取计划、核对哈希并重新检查全部引用。先提交 removing 记录，随后 unlink 并 fsync 父目录，再提交结果。每步 SQLite 写事务都很短，不跨原生文件 I/O。重复完整执行返回原结果，不重新删除后来出现的同名文件。

plan 的 next_cursor 是活文件命名空间中的前进位置，不是固定成员快照。limit 限制检查的对象数，保护对象也占一项；新出现且排在游标之前的对象留到下一次从空游标开始的盘点。不会因“未找到孤儿”就宣称整个磁盘已经回收。

## 引用保护与边界

在同一 SQLite 读视图检查全部 revisions.document_json、所有状态 Job 的 input/result，以及所有 project_media.asset_json。不是只检查当前 head 或 running Job。解析 JSON 后匹配内容标识，等价转义形式不会漏判；未明确识别的扩展元数据中的相同标识也保守保留，允许多保留而不猜测删除。

仅对权威的旧式未固定源字段（旧 revision 的无 version 素材 URI、source-only Job input，以及无 asset_lock 的旧任务快照素材 URI）做当前 inode 解析，保护别名引用。任意用户 metadata 中的 `uri`/`input` 键不引起原生路径访问。缺失的旧外部来源本来就不可用；旧式可变源路径和远程 URL 不因此升级为不可变素材保证。固定版本任务的可复现性仍由 AssetVersion/AssetLock 保证。外部管理员绕过 Host 直接更改数据库/私有目录不属于并发锁协议。

引用预算为总计 64 MiB JSON、单条 8 MiB、100000 行、5000ms 合作式检查；旧式原生源解析另有 5000ms 合作式预算。工作区/原生命名空间枚举各最多 100000 项。超过预算、数据库记录损坏或不能可靠解析引用时，在本次删除之前拒绝，不把未扫描对象判为孤儿。单个文件系统调用不能由这些合作式时间预算抢占。上限由 hostCapabilities.cas_gc 发布。

## 状态、故障与审计

计划状态 planned / executing / complete。逐项状态：

- planned：尚未尝试。
- removing：已经提交删除意图，结果尚未完成确认；不能据此声称文件已删除或仍存在。
- removed：本次执行 unlink 后同步父目录，再提交回执。
- already_absent：重试时确认目标已不存在并同步目录，不猜测是哪个旧进程/外部动作删除。
- retained：执行时找到保护引用，不尝试删除；这是决策回执，不是当前文件可用性证明。
- changed：文件类型/身份不再匹配原计划，跳过；若仍需处理，应生成新计划。

complete 表示全部候选已有终态决策，不表示全部删除，也不表示当前磁盘状态永久不变。逻辑 size_bytes 不是实际回收字节；硬链接、APFS 共享块、快照和打开的句柄可能让空间继续占用。

SQLite cas_gc_plans 保存计划/幂等参数，cas_gc_events 追加逐项状态和可信 request_id/actor；既有 audit_records 在同一事务写入 cas.gc.planned/cas.gc.item，并关联原计划请求。原生删除后若结果事务失败，removing 保留；重试核对当前引用、身份和文件存在性后继续。计划及回执目前持久保留；工作区备份必须包含数据库、CAS 及其他托管目录，不提供直接删除计划历史的接口。

schema 11→12 仅创建空计划和事件表，不伪造过去回收。迁移失败整体回滚。退出客户端或 HTTP 超时不会回滚已发生的删除，也不是取消继续执行的命令。非 Unix 和内存数据库不提供此回收实现；本轮实际验收平台为 macOS x86_64。
