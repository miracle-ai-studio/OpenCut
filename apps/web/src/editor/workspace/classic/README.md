# Classic source adapter boundary

This directory decodes legacy browser input. It does not own current projects,
construct modern ProjectDocument DTOs, mutate editor state or write old stores.
Native application analysis and atomic import remain the shared authority for UI,
CLI, HTTP, MCP and SDK. Unknown editing fields and dependencies remain visible to
native compatibility blockers. The old database and raw snapshot are retained.

`source.ts` is the only reviewed browser-storage reader: existing IndexedDB stores
are read in readonly transactions. Opening an absent database aborts creation.
OPFS handles are opened without `create`; no persisted data is replaced or deleted.
The boundary gate rejects version upgrades, write transactions, write methods,
OPFS creation and modern credential/project persistence in this adapter.
Reads are bounded, cancellable and time out instead of leaving recovery stuck.
Interrupted opens close any late connection. Source snapshots remain unchanged.

`legacy/` comes from the local Classic pure migration transformers (v0 through v31),
not its destructive runner or storage adapters. The MIT license and exact source
hashes are included. Source time/parameter format decoding stays here; current
editing rules remain in Rust application/core. No Rust module, dependency edge,
allowlist expansion or migration exception is introduced.
The decoder checks element identities at every format step and rejects damaged
or unsupported external v1 fields that the historical transformer would filter.
Blank fixtures for all 32 versions do not establish full nonempty parity for every
version, keyframe, resource or dependency. Unknown modernized semantics are still
rejected by native analysis; they are never removed to pass a gate.

Adaptations: deterministic missing scene/track/keyframe identities replace random
IDs; absent presentation dates use a fixed epoch; historical tick rounding uses
the same half-away-from-zero rule without importing the old WASM runtime; record
validation excludes arrays; one unused TypeScript interface is removed. Culori
4.0.2 and its 4.0.1 type declarations match Classic's color decoder and are pinned
only for historical input parsing (https://culorijs.org/api/), not modern rendering.

`recovery.ts` orchestrates the generated native contracts: durable stream uploads,
confirmed offsets, fixed preparation revisions, compatibility analysis, explicit
loss consent and atomic import. Native sessions/events/immutable revisions own
retry identity; the browser persists no second current-project or upload journal.
After import, the existing fixed-revision native promotion upgrades the current
head for editor use without reconstructing a document in the client. Resume
verifies the original immutable import event/revision; an already upgraded or
subsequently edited current head is preserved. Import and promotion are separate
atomic use cases; interruption between them resumes the remaining promotion.
Pausing stops reads/transfers/observation and retains accepted native imports.
Preparation deletion checks the initial native receipt and complete current
bindings against the immutable imported-media records before removing anything;
edited project content or media metadata/duration/kind/URI is preserved.

`bundle.ts` defines only a versioned historical input container, not a modern
project DTO. A bounded JSON header contains original records/timeline context,
followed by actual file bytes, sizes and SHA256. Every original library file is
required, including unused media. JSON-only, incomplete, corrupt or extra bytes
are rejected before publication. Files are sliced/hashed in bounded chunks.

`old-origin-exporter.ts` builds a self-contained, network-free bookmark through
`scripts/build-classic-exporter.mjs`. The product provides that exact bookmark;
it executes at the old site's origin, reads the reviewed adapter and downloads
the binary recovery bundle. It never copies media into a remote service. The
build checks generated bytes and its content-hashed URL. Existing host/packaging
asset boundaries serve `/assets/classic-exporter-<hash>.js`; no root-file allowlist
extension is needed. Private/arbitrary root files remain rejected. Production-site
CSP, browser bookmark restrictions, large-project and
all nonempty historical-format matrices remain separate acceptance boundaries.

Product verification uses `scripts/verify-web.py --suite classic-recovery` with
fresh profiles, synthetic IndexedDB/OPFS data and real native uploads/rendering.
Its receipt, not this implementation note, determines verified status.
